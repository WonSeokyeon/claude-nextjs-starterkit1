# 코드 리뷰 전문 서브에이전트 신설

## Context

현재 이 프로젝트에는 `/code:review`라는 커스텀 슬래시 커맨드(`.claude/commands/code/review.md`)가 이미 존재하며, 가독성·성능·안정성·프로젝트 컨벤션 4대 기준으로 코드를 심층 리뷰하는 로직을 담고 있습니다. 하지만 이는 **사용자가 수동으로 호출**해야 하는 커맨드입니다.

사용자는 이제 "코드 구현이 완료된 직후 자동으로" 코드 리뷰가 이루어지길 원하며, 이를 위해 `.claude/agents/` 폴더에 **읽기 전용 권한(Read, Grep, Glob)**, **model: sonnet**으로 동작하는 전문 코드 리뷰 서브에이전트를 만들고자 합니다. 서브에이전트는 Claude Code가 Agent 도구로 호출할 수 있는 독립된 정의 파일이며, 별도의 컨텍스트에서 실행되어 메인 대화의 컨텍스트를 보호하면서 코드 구현이 끝날 때마다 일관된 기준으로 리뷰를 수행하게 됩니다.

기존 `/code:review` 커맨드의 4대 리뷰 기준과 출력 형식은 이미 검증되어 있으므로, 이를 그대로 서브에이전트의 system prompt(body)로 이식하여 일관성을 유지합니다. 두 진입점(수동 슬래시 커맨드 / 자동 서브에이전트)이 동일한 기준으로 리뷰하도록 합니다.

## 구현 내용

### 1. 신규 파일: `.claude/agents/code-reviewer.md`

Claude Code 서브에이전트 정의 포맷(YAML frontmatter + Markdown body)을 따릅니다.

**Frontmatter:**
```yaml
---
name: code-reviewer
description: 코드 구현이 완료된 직후 실행하여 가독성·성능·안정성·프로젝트 컨벤션 기준으로 변경사항을 심층 리뷰하는 읽기 전용 전문 에이전트. 새 코드를 작성하거나 기존 코드를 수정한 뒤 반드시 사용할 것.
tools: Read, Grep, Glob
model: sonnet
---
```

- `description`은 메인 에이전트가 "언제 이 서브에이전트를 써야 하는지" 판단하는 핵심 근거이므로, "코드 구현 완료 직후 사용"이라는 트리거 조건을 명시적으로 담습니다.
- `tools: Read, Grep, Glob` — 읽기 전용 3종만 부여 (Bash 제외 → git diff 조회는 불가하므로, 리뷰 대상은 메인 에이전트가 변경한 파일 경로를 프롬프트로 전달받는 방식으로 동작. 이는 `/code:review`가 `Bash(git diff:*)`로 변경사항을 자동 탐지하던 것과의 차이점 — 아래 "설계 트레이드오프" 참고)
- `model: sonnet` — 사용자 지정대로 고정

**Body (system prompt):** `.claude/commands/code/review.md`의 아래 섹션들을 서브에이전트 문맥에 맞게 이식:
- 리뷰 기준 4가지 (가독성&유지보수성 / 성능&효율성 / 예외처리&안정성 / 프로젝트 컨벤션 준수) — 원문 그대로 재사용
- 프로젝트 컨벤션 세부 항목(4계층 경계, `components/ui/` 직접 수정 금지, Next.js 16 비동기 API, 검증된 라이브러리 사용)도 원문 그대로 포함
- 출력 형식(🛠 총평 / 🔍 개선 필요 사항 / ✨ 개선 제안)도 동일하게 유지 — 단, 서브에이전트는 파일을 수정할 수 없으므로(Edit 도구 없음) "적용할지 확인 후 진행" 문구는 "메인 에이전트에게 수정 여부를 위임" 뉘앙스로 조정
- 리뷰 대상은 프롬프트로 전달된 "방금 작성/수정된 파일 목록"을 기준으로 함 (Bash 미보유로 git diff 자체 조회 불가)

### 2. 자동 실행 지침: `CLAUDE.md`에 규칙 추가

서브에이전트 정의만으로는 "코드 구현 완료 후 자동 실행"이 보장되지 않습니다. Claude Code는 서브에이전트를 강제 자동 호출하는 훅 메커니즘이 없고, 메인 에이전트(오케스트레이터)가 Agent 도구로 판단해 호출하는 구조이기 때문입니다. 이를 위해 `CLAUDE.md`에 다음 지침을 추가합니다:

```markdown
## 코드 리뷰 자동화

코드 구현(파일 생성/수정)을 완료한 직후에는 `code-reviewer` 서브에이전트를 호출하여 리뷰를 받습니다.
```

이 지침이 있어야 앞으로의 세션에서 Claude Code가 "구현 → code-reviewer 서브에이전트 호출"을 관례로 따르게 됩니다. (Hook 기반의 강제 실행이 아닌, 프로젝트 지침 기반의 관례임을 사용자에게 설명 필요)

## 설계 트레이드오프 (사용자 확인 불필요, 참고용)

- 서브에이전트에 Bash가 없어 `git diff`로 변경사항을 자동 탐지할 수 없음 → 메인 에이전트가 방금 수정한 파일 경로를 명시적으로 프롬프트에 담아 전달하는 방식으로 동작. 이는 사용자가 요청한 "읽기전용(read, grep, glob)" 권한 제약을 지키기 위한 자연스러운 결과.
- 기존 `/code:review` 커맨드는 그대로 유지 (수동 호출용으로 남겨둠). 신규 서브에이전트와 기준을 공유하되 별개 진입점으로 공존.

## 검증 방법

1. `.claude/agents/code-reviewer.md` 파일 생성 후, 임의의 간단한 컴포넌트 파일을 하나 수정
2. Agent 도구로 `code-reviewer` 서브에이전트를 직접 호출해 리뷰 결과가 4대 기준에 따라 정상적으로 출력되는지 확인
3. tools 필드가 read-only(Read/Grep/Glob)로만 제한되어 Edit/Write/Bash 시도 시 거부되는지 확인
